# Data Model: ECDSA P-256 validation parity + live Cleverbase-account signing

This feature introduces no persisted data and no new SDK API types. The "entities" below are the
**test/fixture/harness** constructs the design revolves around — their fields, relationships, and the
validation rules drawn from the functional requirements.

## SignerProfile (mock upstream)

The mock's notion of "which key signs for this CSC route". Replaces the single hardcoded `rsaKey`.

| Field | Type | Notes |
|-------|------|-------|
| `cscBase` | string | the routed base that selects this signer: `/csc/v1` or `/csc/v2` |
| `keyAlgo` | enum | `RSA` \| `EcdsaP256` — drives the `algo` OID and the signing primitive |
| `privKey` | key | parsed from `signer-rsa.key.pk8` (RSA) or `signer-ec.key.pk8` (P-256) |
| `certDER` | bytes | `signer-rsa.cert.der` / `signer-ec.cert.der`, injected into the matching `credentials_info` |
| `algoOID` | string | `1.2.840.113549.1.1.1` (RSA) \| `1.2.840.10045.2.1` (EC public key) — what `credentials/info` advertises |
| `sign(tbs)` | func | RSA: `SignPKCS1v15(SHA256)`; EC: P-256 sign → **raw `r‖s`** (the CSC-v2 wire form the core normalizes) |

**Rules**: exactly one SignerProfile per CSC route; the `algoOID` advertised in `credentials/info` and the
signature bytes returned by `signHash` MUST come from the **same** SignerProfile (no drift — FR-004). The
TSA key is **not** a SignerProfile (it is the timestamp authority's own RSA key, orthogonal to the signer
algorithm).

## SigningCredential (domain, already in the core)

The credential the flow signs with — unchanged in the core; listed for completeness.

| Field | Type | Notes |
|-------|------|-------|
| `keyAlgo` | `KeyAlgo` | derived from the cert key OID by the core (`key_algo_from_oids`) — `Rsa`/`EcdsaP256`/`Other` |
| `certChain` | bytes[] | leaf + issuer chain; the trust anchor for independent verification |
| `signAlgoOID` | string | CSC `signHash` parameter: RSA is `rsaEncryption` (`1.2.840.113549.1.1.1`) while `hashAlgo` carries SHA-256; ECDSA is `ecdsa-with-SHA256`. The CMS `SignerInfo` algorithm remains `sha256WithRSAEncryption` / `ecdsa-with-SHA256`. |

**Rules**: an `Other`/unsupported key MUST be rejected with a specific error, never guessed (Edge Cases,
FR acceptance US1#3).

## SyntheticPKI (fixtures)

The committed, reproducible test PKI (`tests/fixtures/pki/`), regenerated by `gen.sh`.

| Asset | Purpose |
|-------|---------|
| `ca.{cert.der,cert.pem,key.pem}` | self-signed test root; issues both signer certs + the TSA |
| `signer-rsa.{cert.der,key.pk8,…}` | RSA-2048 signer (existing) |
| `signer-ec.{cert.der,key.pk8,…}` | ECDSA P-256 signer (exists; now wired into the mock) |
| `tsa.{cert.der,key.pk8,…}` | RFC 3161 TSA (RSA; orthogonal to signer algorithm) |
| `upstream/credentials_info.json` (one template) | filled per route at serve-time with the selected signer's cert + `algo` OID — a **single template**, not two committed copies (contracts/algorithm-fixtures.md §2) |

**Rules**: filenames are stable (Go `os.ReadFile` + Rust `include_bytes!` depend on them); `gen.sh` MUST
emit exactly these names; both signer certs MUST chain to `ca.cert.der`.

## Authorizer (E2E live harness — new)

The pluggable seam for the Cleverbase user-authorization (SCAL2) step. One method.

| Member | Type | Notes |
|--------|------|-------|
| `Authorize(authorizeURL, state)` | func → `(code, state, error)` | obtains the OIDC callback params for one redirect |
| impl: `Interactive` | — | default; surfaces the URL to a human, captures the redirect callback, resumes |
| impl: `Headless` | — | opt-in; drives an automatable Cleverbase test-credential approval |

**Rules**: selected by `REFSVC_LIVE_AUTHORIZER` (`interactive` default \| `headless`); swapping impls MUST
NOT change the driving loop or the SDK/flow (FR-013); the same `Authorize` is called once per redirect
(service-scope, then credential-scope/SCAL2).

## LiveRunConfig (E2E live harness — extends existing config)

| Field | Env var | Notes |
|-------|---------|-------|
| mode | `REFSVC_MODE` | existing; `fixtures` (default) \| `live` — the master switch the live knobs depend on |
| client id/secret | `REFSVC_CLIENT_ID` / `REFSVC_CLIENT_SECRET` | existing; the real OIDC registration |
| redirect URI | `REFSVC_REDIRECT_URI` | existing |
| environment | `REFSVC_ENV` | existing; `acceptance` (default) \| `production` |
| CSC api | `REFSVC_CSC_API` | existing; `v1_rsa` \| `v2_ecdsa` (run both when both credentials exist) |
| TSA url | `REFSVC_TSA_URL` | existing; enables B-T when present (else B-B only) |
| authorizer mode | `REFSVC_LIVE_AUTHORIZER` | **new**; `interactive` (default) \| `headless` |
| real trust anchor | `REFSVC_LIVE_CA_BUNDLE` | **new**; real Cleverbase issuer chain PEM for live verification |

**Rules**: if the required real-credential settings are absent, the live path is **skipped** (never failed)
and the credential-free suite runs unchanged (FR-009); secrets are CI-secret-only, never committed/logged
(FR-010).

## ProducedSignatureArtifact

| Field | Type | Notes |
|-------|------|-------|
| `pdf` | bytes | the signed PDF (from `/v1/sign/result`) |
| `cms` | bytes | the embedded PAdES/CMS (extracted via `/Contents`) |
| `signatureAlgo` | string | `ecdsa-with-SHA256` for the ECDSA arm |
| `conformance` | enum | `B-B` \| `B-T` (B-T carries the RFC 3161 timestamp) |
| `trustAnchor` | bytes | synthetic CA (credential-free) \| real Cleverbase chain (live) |

**Rules**: verified by the always-on OpenSSL bar (signature + chain + structure + timestamp); optionally by
the profile gate.

## ValidationOutcome

| Field | Type | Notes |
|-------|------|-------|
| `cryptoOk` | bool | always-on OpenSSL CMS/chain/(timestamp)/structure check passed |
| `profileLevel` | enum? | from the opt-in gate: `PAdES-BASELINE-B` \| `PAdES-BASELINE-T` (DSS); null if gate disabled |
| `adesValid` | bool? | from the opt-in gate: pyHanko AdES validation result; null if gate disabled |

**Rules**: a wrong-algorithm / tampered-chain / bad-timestamp signature MUST fail `cryptoOk` (no
false-accept, SC-006); when the profile gate is enabled, `profileLevel` MUST equal the requested
conformance and a cryptographically-valid-but-non-conformant signature MUST fail loudly (Edge Cases).
